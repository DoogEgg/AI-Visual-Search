# 功能验证与检索评测

## 自动化测试

当前测试覆盖扫描与 SHA-256 去重、坏图跳过、递归扫描、元数据、建库批次与进度、索引保存/重载、查询维度和数值校验、模型一致性、旧索引处理、Top-K 排序、页面启动、缺少索引/空查询提示、语义标签表，以及发布文件的隐私白名单。

本次发布验证：Windows / Python 3.13，25 项自动化测试通过。真实模型在 CUDA 环境中建立六张合成插图的 512 维索引（NumPy 后端），六次图片自身检索通过；`a red car`、`a blue car`、`a forest`、`a house`、`sunset over the sea`、`fruit` 在该小演示集的首位结果与插图主题一致。该结果仅是人工可复现的功能检查，不作为真实数据集准确率或泛化效果声明。

页面测试使用轻量模拟编码器，验证的是交互和数据流，不验证模型效果。GitHub Actions 只安装 `requirements-core.txt`，避免每次提交下载大模型。

## 真实模型检查

`python scripts/verify_model.py --offline` 使用默认 CLIP 和六张合成插图，验证图像编码、文本编码、512 维索引保存/读取、六次图片自身检索，以及六个英文描述的 Top-3 返回结果。报告记录运行环境和设备。

图片自身检索验证索引一致性，不是未知图片分类准确率。报告中的 `vector_search_ms` 仅计时已编码查询向量的排序步骤，不包括模型加载、文本编码、网页传输；六张图片上的耗时不代表大规模相册性能。

## 后续正式评测

目前没有完成带独立标注答案的真实相册查询集，因此不报告 Recall@5、Recall@10、mAP、用户满意度或准确率。

正式评测应使用有授权且可脱敏的图片集，为每个查询标注相关图片集合，并与文件名/关键词搜索等基线比较。分别记录 Recall@K（相关图片被找回的比例）、mAP、冷启动时间、建库吞吐、查询编码及检索总延迟和资源占用。中文、英文、颜色属性、动作和复杂组合查询应分组评估；不能用相似度分数代替正确率。
