# 实现与运行边界

数据流：本地文件夹 → 图片校验与去重 → CLIP 图像编码 → L2 归一化 → 本地持久化 → 文本/图片向量 → Top-K 排序 → 页面展示。

## 扫描与数据准备

`image_scanner.py` 按支持的扩展名递归扫描，以 Pillow 校验图片并提取名称、宽高、大小、修改时间和 SHA-256。相同文件字节只保留一个；视觉相同但压缩或裁剪不同的图片不保证被识别为重复。坏图加入跳过列表，不修改原文件。

## 编码与检索

默认预训练编码器为 CLIP ViT-B/32，512 维向量。`clip_encoder.py` 将图像转为 RGB，以批次进行前向推理；文本经 tokenizer 编码，输出映射到相同的特征空间。采用推理模式，不训练、不反向传播。

图像和查询向量归一化后，内积等于余弦相似度。NumPy 路径执行矩阵乘法并排序；可选 FAISS 路径使用精确的 `IndexFlatIP`。两者均不包含倒排文本检索、重排序模型、生成式回答或 Agent。

## 持久化与模型一致性

默认保存：

- `product_data/vector_index/image_embeddings.npy`：float32 向量矩阵。
- `product_data/vector_index/image_metadata.json`：格式版本、编码器名称、维度和图片元数据。

加载检查向量形状、数量和维度；查询时核对当前模型名称与索引来源，避免不同编码器之间直接比较向量。旧版没有模型名称的索引需要重新建立。模型标识记录的是名称，不包含权重 revision；需要严格复现或更换同名权重时，也应重新建库。

默认位置可通过 `IMAGE_SEARCH_DATA_DIR` 环境变量覆盖。索引不是可跨电脑直接移植的照片包：它保存绝对路径，不包含照片原文件。当前写入方式不是多文件原子事务；请勿并发建库，写入中断后重新建立即可恢复。

## 运行方式

`run_product_app.py` 默认在 `127.0.0.1:8502` 启动 Streamlit。通过资源缓存复用已加载编码器，通过会话状态复用向量索引。多会话共用同一磁盘索引，不具备租户隔离；应用面向个人本地演示，不是多用户生产服务。

默认关闭源文件自动监听，避免 Streamlit 在扫描 PyTorch/Transformers 模块时产生兼容性警告。网页交互照常运行；修改代码后需重启应用。

关闭浏览器/进程不会删除磁盘索引。原图片路径仍然有效时，重新启动可以继续检索。上传的参考图片不持久化；关闭会话后要重新上传参考图，但不需要重建相册索引。
